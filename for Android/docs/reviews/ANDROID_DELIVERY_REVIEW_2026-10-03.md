# Android 交付与开源就绪审查（2026-10-03）

## 结论

**修复本次发现的阻断项后，Android 端达到「公开 alpha」开源发布水平；尚未达到稳定版（1.0）交付水平。**

- 核心链路（新建会话 → 提交任务 → 流式回复/工具状态 → 审批 → 完成/失败原因 → 生成文件交付）在真机上端到端可用。
- 自动化测试覆盖充分：Python 885+ 项、Web 界面 188 项（jsdom），APK 与仪器测试 APK 均可编译。
- 一个会直接导致开源发布失败的问题已修复（见 B1）。
- 剩余问题都不阻断 alpha 发布，但在宣称稳定之前应处理（见「未解决问题」）。

## 安全审查要点

- **本地服务鉴权**：`/console` 与静态资源需要令牌；API 需要 Bearer 令牌并按 read/write/approval 分权；校验 Host 头（防 DNS 重绑定）；不发 CORS 头。未发现绕过。
- **WebView**：导航限定 `http://127.0.0.1:8080`，其他链接交给系统浏览器；HTML 预览 iframe 为无脚本沙箱；交互预览在独立 Activity 中且无原生桥。
- **密钥**：未发现真实密钥；唯一命中是被忽略的 llama.cpp 构建缓存中的示例占位符。
- **已知风险（未解决，P2）**：本机端口抢占。若其他应用在引擎启动前占用 8080，WebView 会把令牌和原生桥交给该页面。建议改用随机端口加启动时握手校验，或改为 `WebViewAssetLoader` 承载界面。

## 第二轮：未解决问题的处理（2026-10-04）

| 原优先级 | 问题 | 处理 |

| P2 | 无法删除会话 | 新增归档：`POST /sessions/{id}/archive`，写入与桌面端共用的会话展示记录并发出 `session.presentation.changed` 事件。事件库只追加不删除，所以归档会隐藏会话、保留完整记录，并可在会话列表「已归档」中恢复。运行中的任务会拒绝归档（409）。界面入口在会话列表与「会话名称」页 |

| P2 | 仪器测试在真实数据中残留工作区 | `MobileWorkspaceUiDeviceTest` 与 `SharedFileIntentTest` 结束时都会移除所建工作区；其余仪器测试不创建真实工作区 |

| P2 | 仅中文；后端错误英文直出 | 新增英文界面（跟随系统 / 中文 / English）。Web 界面 700 多条文案、原生启动页、模型设置对话框、通知与系统文件管理器入口均已双语。已知后端错误在中文界面译为中文，原生桥返回的错误在英文界面译为英文。测试会在新增文案缺少英文时失败 |

## 第三轮：液态玻璃重做（2026-10-04）

旧实现只是 `backdrop-filter: blur()` 加半透明白底，放在近乎纯白的页面上，看起来就是一块浅色面板。参照 Apple 的 Liquid Glass 设计说明（WWDC25「Meet Liquid Glass」：靠边缘的透镜折射、高光和下方内容读出玻璃感，而不是靠模糊）与 kube.io 的网页实现方法，改为：

| 问题 | 处理 |
|---|---|
| 没有折射 | `static/liquid-glass.js` 按每个玻璃元素的尺寸生成位移贴图（凸面 squircle 轮廓 + 斯涅尔定律，n = 1.5），通过 SVG `feDisplacementMap` 作为 `backdrop-filter: url(#…)` 使用，再叠加轻微磨砂、饱和度和左上方向的镜面高光。尺寸变化时重建；仅 Chromium（Android WebView）启用，其他引擎、系统「降低透明度」和低内存设备退回普通模糊。真机（WebView 153）用条纹测试图确认边缘弯曲生效 |
| 背景纯白，玻璃无从体现 | 玻璃模式新增背景：极光、晚霞、深海、青柠、石墨五种预设（浅色/深色各一套），纯色，以及自定义壁纸。自定义图片在本机缩放到 1600 px 内并转成 JPEG 存在本地（3000×4000 的 7 MB 图片存为 83 KB），只接受页面自己编码的 data URL。系统状态栏颜色随背景变化 |
| 边框像白色的框 | 去掉所有白色实线边框、均匀内发光和内描边；高光只集中在迎光的角和对角，并沿边缘渐隐，以“滤色”方式提亮下方颜色而不是覆盖白色。折射版玻璃几乎无底色、磨砂很轻，透镜更强，并加入红绿蓝分别偏折的色散 |
| 骁龙 888 上滚动卡顿 | 实测滚动仅 23 帧/秒；对照实验确认开销全部来自 SVG 折射滤镜（纯模糊为 90 帧，即屏幕上限）。改为：静止时用带色散的完整滤镜（静止画面不重绘，无开销），滚动时换成单次折射；磨砂与饱和度改用 CSS 滤镜函数；高光改为静态叠加图；大面板只用单次折射。滚动提升到 86–88 帧/秒（95% 的帧在 11 ms 内）。贴图只计算边缘带、相同尺寸共用、编码移出主线程，全部贴图约 230 KB |
| 可以双指缩放 | 页面 viewport 禁止缩放，WebView 关闭内置缩放（文字大小仍可在设置中调整） |
| 「开始一个新任务」卡片突兀 | 改为同一种玻璃面板；新增流光、光斑、网格、彩带、暮光五种适合玻璃折射的背景 |
| 二级菜单不是玻璃 | 抽屉、设置面板及其所有子页面（分组、行、输入框）改为同一种玻璃：低底色 + 更强磨砂保证可读 |
| 壁纸上文字难读 | 有壁纸时，回复与空状态放在半透明底板上；抽屉与设置面板提高不透明度 |
| 快捷任务过时 | 改为「总结要点、翻译润色、做个网页、分析数据」；这些是开放式任务，点击后把开头填入输入框，不再直接发送 |
| 无法调试页面 | Debug 包启用 WebView 远程调试（Release 不受影响） |

## 第四轮：中途补充与断线恢复（2026-10-05）

| 问题 | 原因 | 处理 |
|---|---|---|
| 不能在任务执行中插话 | 引擎核心已支持 `steer_turn`（桌面端在用），移动端没有接口 | 新增 `POST /mobile/tasks/{id}/steer`。任务执行或等待审批时，输入框提示「补充说明」，发送即加入当前任务：引擎立即持久化，在下一个模型/工具步骤之间作为用户消息采纳，模型原本要结束时也会继续回应。任务已结束时文字放回输入框。真机用 DeepSeek 实测通过 |
| 「Failed to fetch」后一直「任务状态待确认」 | ① 引擎每次重启都会换新令牌，旧页面的令牌全部失效，「重新连接」只是重试同一地址，永远失败；② 请求处理中未预期的异常会让 HTTP 服务直接断开连接，页面只看到 Failed to fetch | 页面在连不上或令牌被拒时请应用接管：应用按需启动/替换引擎并用新令牌重新载入页面（草稿与任务不丢）；切回应用时也会检查。网关对任何未预期错误都返回 JSON（忙碌 503、内部错误 500）并把堆栈写入 `agent-data/logs/gateway-errors.log` |
| 出错后重启应用卡在「正在确认本地服务身份」 | 新引擎先写入 `serve.token` 再绑定端口；若旧引擎卡住仍占着端口，新令牌被发布但端口上的旧引擎无法证明它，应用无限等待。引擎在独立进程，重开应用无效 | 令牌改为绑定端口后原子写入；身份确认连续失败约 10 秒即结束卡住的引擎进程并重新启动，记录到 `engine-restarts.log`。真机模拟令牌不匹配：约 8 秒自动换掉引擎并恢复页面 |
| 卡死原因无从查起 | — | 引擎事件循环停止响应 45 秒时，由不依赖 GIL 的计时器把所有线程堆栈写入 `agent-data/logs/engine-stalls.log`，下次出现即可定位 |
| 诊断日志拿不到 | 日志在应用私有目录，普通手机无法读取 | 「设备与工具」页新增「分享诊断日志」：把版本、引擎状态、三份引擎日志和本应用最近的系统日志打成一个文本文件，经系统分享面板发送。引擎令牌、所有已存 API 密钥、Bearer 令牌和网址中的 token 会被遮盖（真机核对过） |
| 引擎启动中被重启，留下半停止的引擎（诊断日志首次即捕获） | 后台恢复任务在服务启动时立即执行一次，此时引擎尚未写出令牌，被误判为死亡并强制重启；启动中的引擎 10 秒内停不下来，原代码直接放弃，留下 HTTP 已关闭但任务仍「运行中」的引擎。这正是「Failed to fetch → 重连无效 → 重开卡在确认身份」的完整链条 | 恢复任务不再重启启动中（90 秒内）的引擎，首次周期执行推迟一个周期；旧引擎 10 秒内停不下来时结束整个引擎进程，由服务和应用拉起干净的新引擎；关闭过程若卡住，8 秒时把线程堆栈写入 `engine-stalls.log`。真机验证正常重启、强制停止后启动、令牌不匹配三种情形 |
| 只含思考与工具调用的中间步骤一直显示「正在执行…」 | 该步骤结束后未清除占位文字 | 只显示其思考过程；两者都没有时不留卡片 |
