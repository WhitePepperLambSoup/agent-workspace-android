# Android 上下文压缩与本机性能设置

目前已有自动摘要与上下文裁剪，但不能称为成熟、不会丢失要求的长期记忆。程序边界经过修复和回归验证；原始 Qwen3.5-0.8B 的五场景真机摘要独审为 0/5 完整忠实交接，不能默认依赖该模型的摘要保留任务状态。

## 当前行为

新配置在内置本机端点默认关闭摘要，云端默认开启，新任务与恢复任务均读取有效设置。已保存的开关值及显式环境设置保持优先；旧版本没有选择来源记录，无法区分自动写入的值和用户主动选择，因此保留全部已有布尔值。无关设置保存不会把隐式默认值写成显式选择。二级菜单把本机摘要标为实验功能，说明 0.8B 的待办遗漏和错误完成状态、其他本机型号尚未完成语义验收；用户仍可自行开启。

云端摘要使用当前服务商和模型，增加的 token 与费用纳入任务统计。普通任务的原始会话记录保留在存储中。摘要输入不执行工具，交给后续模型时保持数据边界。关闭摘要仍会在超出窗口时裁剪早期上下文，不能等同于无损长期记忆。新默认策略已完成本地主机验证，r4 真机设置与菜单、r5 自动文本规划及 provider 创建的结果见下表；原始失败记录仍保留。

历史以完整正文、工具名称及参数、调用编号、信任等级和敏感度序列化，图像保留指纹及原档引用。超过容量时，运行器连续分片摘要，每片携带已有摘要，按照实际请求编码和剩余输入、输出额度拟合。当前请求及其工具调用/返回组始终保留；软压缩目标可退让到硬容量。摘要需要裁短时保留首尾并明确标示省略。

每片摘要记录来源覆盖区间、结束状态、用量和模型请求编号。只有正常完成的完整处理结果可复用；拒绝、截断、输出越界、工具提议或缺失完成状态均不伪造成功。取消传播到调用方，已收到的真实用量仍计入统计。缓存键包含完整历史、服务商、模型及摘要约定版本。

第三版摘要约定明确保留待办：没有已验证结果、明确取消或替代要求时，用户请求仍未完成。没有工具结果不能推出没有待办，也不能凭空称历史被截断。旧约定生成的摘要不会按相同历史缓存复用。

本机分词使用已安装 GGUF 的词表；计数不会切换推理权重。计数、本机输入容量和共享运行器采用同一 token 单位，避免把真实 70 token 当作 94 token。累计额度耗尽时不再发请求，真实本机文本计数超过剩余额度时在生成前拒绝；累计额度不会逐轮缩小用户选定的上下文窗口。

## 本机设置

二级菜单支持模型范围内的任意整数上下文、自动或自定义线程及超时，并可把推荐值填入尚未保存的设置草稿。Qwen3.5 上限为 262144 token；自动规划不再统一限制到 32768。手动容量的内存估算作为建议，真实分配失败会明确返回。

默认创建 provider 时按纯文本规划，不因已经下载视觉 projector 而预留视觉内存。显式图片规划单独计入 projector、视觉工作集及更高的物理计算预留。自动推荐按保守的 balanced 物理 RAM 预算计算，即使保存的执行模式是 extended 也不依赖 swap；手动 extended 的内存估算仍是建议，不能保证实际分配成功。当前文本 provider 收到图片时不会自动改用图片规划推荐的较小上下文；需要合适的手动容量，否则可能被现有原生分配保护拒绝。

可取消的设备测试通过同 UID 私有引擎 IPC 执行，使用资源预留，结束后释放。界面分别显示尝试的容量、真实分配容量、实际输入长度、处理与生成速度、首 token 延迟及 RSS 采样峰值。VmHWM 明确为进程历史峰值。短输入测试不证明完整 256K 输入已经可用，测试不会改写保存的设置。

响应丢失或成功响应缺少预留编号时，显示预留状态未知与恢复提示。固定长度流式 POST 避免自动重发可能已经执行的请求。测试结束会重新读取真实忙状态；其他活跃任务继续锁定设置按钮。

## 仍然存在的边界

摘要属于有损压缩，质量取决于当前模型。新增 `session_history` 已在工作区实现当前会话的原文字面检索和分段读取，实际运行器将结果标为不可信、敏感数据，遵循既有外发授权。关闭摘要后的裁剪也提供回查入口。Android 根据实际可用工具目录提示先选择工具；有明确工具限制时不能选择未允许的历史工具。

当前回查是程序功能，模型主动使用与正确遵守原文尚未验收。历史按事件分页向前搜索，每次扫描至多 200 个事件，零命中且有后续记录时仍提供 cursor；读取每次至多 8192 字符，可连续读取完整已存字段。这些单次页大小不会限制历史总深度，也不能恢复持久化前已被截断的工具输出或原始图像像素。原始图片需通过原档引用重新读取。

主机已通过实际 SQLite、运行器和受控 Android 桥接测试。独审发现缩短摘要会丢失下一轮回查标记，已修复为不参与正文缩短的外层标记；r6 原 APK 保留且未安装，r7 隔离真机回查测试通过。r8 已覆盖安装，包含后述服务启动恢复修复。没有充分的多轮长任务模型语义评估，不能承诺每条要求和每个工具结果都被保留。

下一任务在预算计算之前重新检查，恢复时采用真实规划；仍失败时在正常任务生命周期内保存用户输入及失败事件，避免用内部占位容量裁剪原文或启动模型生成。直接 provider 推理也检查。二级菜单明确显示等待内存恢复，错误与下次重查说明可见，设置可调整；非法设置和畸形规划不被忽略。
