# 工作报告

1. 收集材料：用户给的文字、附件（read_document / read_file）、工作区里相关的笔记。缺关键信息（时间范围、汇报对象、篇幅）时先问一句；只缺细节就先写，标出待补充处。
2. 结构（按类型取舍）：
   - 日报：今日完成 / 遇到的问题 / 明日计划；
   - 周报、月报：本期重点成果（量化）/ 进行中的工作与进度 / 问题与风险 / 下期计划 / 需要的支持；
   - 年度总结、述职：概述 / 主要业绩（3～5 项，每项说背景、行动、结果和数据）/ 不足与改进 / 下一年目标。
3. 写法：
   - 结果在前，过程在后；能量化就量化（完成率、数量、节省的时间或金额）；
   - 用户材料里没有的数字不要编，写「（待补充：xx 数据）」；
   - 语气正式但不空洞，少用「圆满」「显著」这类空话。
4. 输出：直接在回复里给正文；用户要文件时用 create_docx（Markdown 转 Word）存到工作区 `reports/`，并给出文件链接。
