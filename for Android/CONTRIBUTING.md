# Android 贡献与验证

Android 适配、原生桥和移动 UI 在本目录；共享运行核心在 `src/agent_workspace`。改动前检查仓库已有未提交修改并协调文件所有权，保持已有会话、凭据、草稿、模型选择和签名身份。不要为了验证 Android 功能顺便改动桌面代码。

使用 [固定构建环境](10_APK_BUILD_AND_RELEASE_GUIDE.md)。提交前至少完成构建，并在真机上验证改动的行为；目录中存在文件不能代替工具执行，catalog 条目不能代替模型推理或工作流测量。

```sh
uv run --frozen python "for Android/build_release.py" --check
uv run --frozen python "for Android/build_release.py" --prepare-only
```

所有管理功能放在二级菜单。模型和工具依赖记录官方/社区发布者、不可变 revision、确切文件、字节数、摘要和许可；只在验证和实际加载/执行成功后广告能力。保留按服务来源隔离的云凭据，不允许本地模型失败后隐式发送到云端。保护输入不进入录制/结果/日志。

工作流写动作通过当前 task policy 和 approval broker；每次使用新树选择语义目标。已执行或 unknown 动作禁止重试，中断与用户取消分别记录，恢复需要显式确认与最后状态检查。任何恢复修复都要验证重复动作、丢失结果、重启、审批和取消这几种情况。

真机验证先得到授权，正常解锁，使用覆盖安装保留数据。不要修改 debug 签名、卸载、清数据或绕过安全 keyguard。报告具体设备/OEM/API、应用版本、模型摘要、预算、测量结果、跳过项与系统限制，并恢复所有临时设备设置。

提交和分发前检查 `git status`。`.gitignore` 与源码导出脚本排除构建/模型/设备/签名状态；不得添加真实密钥、token、数据库、私人 UI 截图、备份、权重或个人 SDK 路径。分发第三方二进制时保留 notices、对应完整源代码与修改摘要；不能仅放一个上游链接替代应随包提供的材料。
