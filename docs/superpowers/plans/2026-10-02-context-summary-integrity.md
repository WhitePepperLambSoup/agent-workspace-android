# 上下文摘要完整性修复

用户要求减少过早压缩，并询问现有压缩是否成熟。实际 Runner 回归发现摘要输入截到每条前 4000 字符、缓存忽略尾部和工具参数、摘要请求越过容量、取消被吞、未完成摘要被当作完成，以及软目标可能删去当前任务。

实施范围：

1. 用完整正文、信任/敏感度、工具调用及图像指纹计算版本化摘要键。旧缓存不得按消息数猜测复用。
2. 按实际请求编码预算分段处理完整历史，携带上一段摘要；每次摘要调用遵守剩余输入与输出额度，保留用量、结束原因和覆盖范围审计。未完整结束的结果不得作为可复用摘要。
3. 传播任务取消；普通提供商失败保留现有回退。摘要输入不得执行工具或把历史数据当新指令。
4. 重建请求始终保留当前任务及工具调用/返回顺序。软压缩目标可以退让到硬容量，不能靠删除当前任务适配。
5. 对实际 Runner / SQLiteStore 执行已失败的完整性回归，并覆盖多段计费、旧缓存、图片指纹与硬容量无法满足的情形。

Android 真实分词预算、可调容量、线程、超时及设备测试由上下文设置协作者实施。正式训练使用经过独立审查的隔离源快照，当前生产修复不改变其冻结数据或评估代码。

验证只能证明输入覆盖、预算、缓存、取消和审计等程序性质。摘要模型是否忠实保留每个约束仍需模型层面的独立长任务评估，不能因这些程序测试通过便宣称成熟。

真实手机的第一轮摘要保留了文件名、中文与日期，却把没有执行证据的文件请求说成没有未完成工作，并无依据地称完整输入为截断日志。独审判定语义失败，原证据保留。通用摘要约定现明确：除非有已验证结果、取消或替代要求，用户请求仍为待办；没有工具结果不能推出没有未完成任务。摘要约定版本加入缓存键，避免复用旧错误摘要。复测覆盖待办、失败、部分完成、需求变更与完成证据，分别保存真实输出供独立审核，不以关键字或正常结束替代语义判断。

五场景第三版约定真机摘要独审为 0/5 忠实完整交接；每场景仅一次生成，不继续调提示取样挑结果。程序完整性通过和语义失败分别保存。基于这份质量证据，新增配置的本机摘要默认关闭，二级菜单明确标为实验功能。保留已有布尔选择与显式环境值，无关设置保存不固化隐式默认；云端默认及用量计费保持。该策略修复不修改训练源、模型权重或评估门槛。
