# 压缩后回查当前会话原文

用户此前授权按推荐修复上下文与补齐功能，并允许自主实施。本项沿用该授权，解决已确认的缺口：原事件仍保存，模型却不能在摘要或裁剪后查回原文。现有本机摘要实验策略继续有效；原始 0.8B 五场景 0/5 的质量结果不因增加回查而变为通过。

采用现有 SQLite 事件分页和文本存储，不增加数据库结构、向量服务或第二个模型。单靠更强摘要仍是有损压缩；加载全部原文又会超过窗口。选择按需检索及分段读取，保留有限请求大小并允许连续翻页到任意已存事件。

新增只读 `session_history` 工具，构造为 `SessionHistoryTool(store, workspace)`，由 `ToolExecutionContext.session_id` 确定唯一会话，并验证会话所属工作区。输入不接受其他会话 ID、数据库路径或任意字段。工具使用 `MEMORY_READ`，`side_effect="none"`。

`search` 接受非空字面查询、可选正整数 cursor、1–20 的 limit，默认 10；按事件序号向前检索 `message.created` 用户/助手/工具消息，以及实际 `tool.proposed`、`tool.started`、`tool.settled`、`tool.failed`、`tool.rejected`、`tool.unknown` 等执行记录。结算和未知状态均不能自动推断为任务成功。每次有有限扫描额度，返回匹配的 sequence、事件类型、字段、字符偏移、片段，以及继续扫描的 cursor。扫描额度耗尽不等于全部历史中没有结果。查询只做本地字面匹配，不发送网络请求。

`read` 接受正整数 sequence、可选 field（`content`、`tool_calls`、`event_data`）、非负字符 offset、256–8192 的 max_chars（默认 4096）。消息正文原样分段；结构化字段以明确标示的规范 JSON 分段。下一偏移和是否结束支持重建全部已存字段。返回的 sequence 必须属于当前会话及允许的对话/工具事件，不能通过序号读取设置、凭据或其他内部事件。存储前已截短的工具输出不能被恢复；图片只返回已存引用或元数据。

检索和读取结果包含来源、事件类型及数据性质，不把提议当执行完成。全部历史结果在运行器中标为 `UNTRUSTED_DATA` 和 `SENSITIVE`，进入现有敏感内容外发授权流程。不能只在返回 JSON 中放一个敏感标签。旧用户文本也不升级为当前可信指令。

注册表提供该工具，Android 本机工具选择器能发现它。压缩提示仅在该工具可用时说明如何搜索、按结果序号读取和核对执行结果；有摘要和无摘要的裁剪路径都提供入口。提示不声称所有要求均已保留。

验证实际 SQLite 会话隔离、当前上下文绑定、超过旧上下文加载范围的检索、字面查询及 cursor、Unicode 分页重建、工具参数/失败/成功来源、非法字段和内部事件拒绝；运行器验证压缩后回查、摘要/回查信任等级和敏感数据外发拦截；Android 验证工具选择、源打包以及隔离会话的真机执行。测试程序成功与模型主动使用回查的质量分别记录。

冻结的正式 V5 训练目录、数据、权重、303 个 source pins 和门槛不可改变。新生产能力没有训练后质量证据时，不能把该训练 run 的结果解释为它已经学会了回查。

## 真机验收发现的启动故障

r7 历史回查隔离测试通过后，实际服务因自动上下文规划返回 `insufficient_memory` 而在 provider 构造时退出。原生规划正确报告当前物理内存不足；错误在 Python 工厂把这一暂时不可用状态升级为整个服务器启动失败，导致设置与诊断也不可访问。

保留原生规划及生成内存检查，仅将结构化 `insufficient_memory` 延迟到推理请求。provider 保存原始失败规划、自动设置 0 及 extended 模式；临时内部容量不能展示为可用上下文或用于裁剪。下一任务在计算请求预算前重查一次，恢复时采用实际规划容量，仍失败时在正常任务生命周期内报错，并保留用户消息及失败事件。直接调用 provider 同样在生成前检查。健康 provider 的规划在已准备的任务中保持一致；非法设置和畸形规划仍拒绝。

二级菜单明确显示等待内存恢复，提供原错误及下次推理重查说明，保持设置可调整。诊断使用未恢复 provider 的保存配置进行建议计算，不能把内部占位容量当作手动配置或实际分配。新增隔离真机测试使用受控桥接和真实 runtime/HTTP/SQLite，验证低内存启动、设置访问、失败不裁剪、恢复容量及原历史；不调用原生生成或重复摘要取样。
